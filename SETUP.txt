# Roll Call — Daily Quota Training Tracker

A static site (for GitHub Pages) with a Google Sheet as the data store.

## Files

- `index.html` — home page, three buttons
- `training.html` / `training.js` — the daily quota submission form
- `weekly.html` / `weekly.js` — the weekly run quota submission form
- `roster.js` — shared bunk → name roster, used by both forms
- `data.html` / `data.js` — the viewer (switches between daily and weekly views)
- `style.css` — shared styling
- `config.js` — **you edit this** to point at your Google Sheet
- `apps-script.gs` — backend code, pasted into Google Apps Script (not hosted on GitHub)

## Why a Google Sheet?

GitHub Pages only serves static files — it can't write to a text file or run a
server. Google Sheets + Apps Script gives you a free, shared, always-on backend
that both writes entries (with timestamp to the second) and serves the data
page, and it doubles as the literal spreadsheet you asked the "Data Entries"
button to link to. You can open the sheet directly any time to see the raw log.

## Setup (10 minutes, one-time)

### 1. Create the Sheet
Go to [sheets.google.com](https://sheets.google.com) → new blank spreadsheet.
Name it something like "Roll Call Data". Leave it empty — the script creates
the "Data" tab and headers automatically on first submission.

### 2. Add the backend script
In the Sheet: **Extensions → Apps Script**. Delete any starter code, then
paste in the entire contents of `apps-script.gs`. Click the save icon.

### 3. Deploy as a Web App
- Click **Deploy → New deployment**
- Click the gear icon next to "Select type" → choose **Web app**
- Description: anything (e.g. "Roll Call API")
- **Execute as:** Me
- **Who has access:** Anyone
- Click **Deploy**, authorize the permissions Google asks for (it'll warn
  it's an unverified app since it's just yours — click Advanced → Go to
  project → Allow)
- Copy the **Web app URL** it gives you (ends in `/exec`)

> Whenever you update `apps-script.gs` later (like for this feature), paste
> the new code into the same Apps Script project, then **Deploy → Manage
> deployments → edit (pencil icon) → New version → Deploy**. Just saving the
> script doesn't update the live URL — you need a new version each time.

### 4. Connect the site to the Sheet
Open `config.js` and replace the placeholder:

```js
const API_URL = "https://script.google.com/macros/s/AKfycb.../exec";
```

### 5. Publish to GitHub Pages
Push all these files to a GitHub repo (all in the root, or in a `/docs`
folder), then in the repo: **Settings → Pages → Deploy from a branch** →
pick your branch/folder. Your site will be live at
`https://yourusername.github.io/your-repo-name/`.

## How the pieces fit together

- **Submitting the form** sends a POST request straight from the visitor's
  browser to your Apps Script URL, which appends a row to the "Data" sheet:
  timestamp, date, time (to the second), bunk, name, pushups, situps, squats,
  and the formatted run string.
- **The Data Entries page** sends a GET request with a date, and the script
  returns every row matching that date as JSON, which the page renders as a
  table sorted by bunk number.

## Weekly Run Quota

The "Weekly Run Quota" form logs just a bunk, name, and total run distance —
no run type needed. It writes to a separate sheet tab (`WeeklyRunQuota`,
created automatically on first submission) rather than the daily `Data` tab.

Each submission is automatically bucketed into a week number based on when
it's submitted, using Singapore time:

- Week 7 = Monday 00:00 SGT on 17/08/2026 through just before Monday 00:00
  SGT on 24/08/2026
- Week 8 = the following Monday–Sunday, and so on

This is computed server-side in `apps-script.gs` (`computeWeek_`), so it's
always based on the actual submission time — not something you need to set
manually. If the program's start date ever changes, update
`WEEK_7_MONDAY_UTC_MILLIS` in that file.

On the Data Entries page, the new "Log Type" dropdown switches between the
two views: daily entries (week + day, six columns) and weekly entries (week
only, three columns: Bunk, Name, Total Run Distance).

## Run string format

- No run at all (or "No run" picked, nothing else added) → `0`
- Exactly one run logged → `Threshold 5km`
- More than one run logged → `(Threshold 5km) + (Intervals 8 x 400m)`

For non-interval runs, only the numeric part of whatever you typed into
Distance is kept, with `km` appended directly (no space) — so "5", "5 km",
and "5km" all become `5km` in the log. Intervals still store as
`sets x distance`, exactly as typed (e.g. `8 x 400m`).

## Week / day dropdown logic

Week 7's Monday is fixed at **17/08/2026**. Every later week just adds 7 days,
and each week only offers Monday–Thursday. This is computed in `data.js` —
if the training schedule ever shifts, update the `BASE_MONDAY` constant there.

## About the font

Avenir is a commercial font (Linotype/Apple) that isn't licensed for free
web embedding, so it can't be bundled into the site the way a Google Font
can. The CSS requests it directly — `font-family: Avenir, 'Avenir Next', ...` —
so it'll render as true Avenir on any device that already has it installed
(most Macs and iPhones do). On Windows/Android, where it's usually not
installed, it'll fall back to a similar-looking geometric sans. If you want
identical rendering on every device regardless of what's installed, that
requires a licensed web font file, which I can help wire in if you get one.

## Timezone

The `Date` and `Time` columns are generated with the timezone hardcoded to
`Asia/Singapore` in `apps-script.gs` (`TIMEZONE = "Asia/Singapore"`), so
they'll always show the correct Singapore time regardless of any account or
browser settings — no config needed on your end.

One cosmetic note: the raw `Timestamp` column (first column, a real
date/time value rather than formatted text) will *display* using the Sheet's
own timezone setting, since Sheets renders Date objects locally. If you want
that column to visually match too, set the Sheet's timezone with **File →
Settings → General → Time zone → (GMT+08:00) Singapore**. This doesn't
affect the `Date`/`Time` columns or anything the website reads — it only
changes how that one raw column looks if you open the Sheet directly.

## Troubleshooting

- **Nothing loads on the Data Entries page:** double check `config.js` has
  the real URL (not the placeholder), and that the deployment access is set
  to "Anyone," not "Only myself."
- **Submissions don't seem to save:** open the Sheet directly and check the
  "Data" tab — Apps Script web apps sometimes block the browser from reading
  the POST response (a CORS quirk), so the form shows a success message
  optimistically. If rows genuinely aren't appearing, re-check the deployment
  settings in step 3 above, and make sure you deployed a *new* deployment
  (not just saved the script) after any edits — Apps Script requires a fresh
  deployment version to pick up code changes.
- **Wrong dates in the dropdown:** confirm `BASE_MONDAY` in `data.js` matches
  the actual Monday of week 7 for your program.
